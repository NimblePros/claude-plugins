# Presentation patterns

## Slide deck patterns

- Use an opening slide that states the problem or promise plainly.
- Prefer one main idea per slide.
- Use diagrams, screenshots, and short labels instead of speaker-script paragraphs.
- End sections with a summary or transition so the audience can keep the thread.

## Demo patterns

- Demo the happy path first; save debugging stories for discussion unless they are the point.
- Keep the environment deterministic: seeded data, stable accounts, predictable inputs.
- Prepare fallback screenshots or short clips for every critical moment.
- Narrate intent before clicking so the audience knows what to look for.

## Recorded video patterns

- Front-load the payoff in the first minute.
- Script the opening, transitions, and close, even if the body stays conversational.
- Remove dead air, loading time, and repeated setup steps when editing.
- Zoom in on important UI or code details rather than hoping they are visible.

## Pacing guidance

- Target fewer slides than you think you need.
- Leave explicit time for transitions, questions, and demo latency.
- Cut secondary material into an appendix instead of compressing the main story.

## Common failure modes

- Too much context before the value becomes clear
- Slides that duplicate the full spoken script
- Demos that depend on fragile network or environment state
- Endings that stop without a concrete takeaway or call to action
